# Noveria — правила работы над проектом

## 1. Что это за проект

**Пошаговая стратегия** в духе Civilization IV и Rome: Total War, но с
**реалистичной макроэкономической агентной моделью** вместо абстрактных
«молотков» и «золота из воздуха».

Отличие от жанровых игр: экономика не рисуется поверх геймплея. Жители
формируют обеспеченный деньгами спрос, рынок сопоставляет его с реальными
запасами, фирмы покупают сырьё, производят и возвращают прибыль в оборот.
Дефицит, цены и бедность — **следствия** расчёта, а не скриптовые события.

Ключевые обещания модели:

- деньги не создаются и не исчезают — только переходят между счетами;
- товар нельзя купить раньше, чем он произведён;
- логистика, труд и природные ресурсы физически ограничивают выпуск;
- у каждого дефицита есть проверяемая цепочка причин.

### Технический статус

| Слой | Состояние |
|---|---|
| Ядро экономики и мира | Python 3.12, модульный монолит |
| Хранилище | графовая БД **LadybugDB** (`ladybug==0.22.1`) |
| Интерфейс сейчас | Streamlit (`ui/`) — отладочный, не целевой |
| Интерфейс в планах | **Godot**, ядро подключается снаружи |
| Лаборатория | `core/lab*.py`, `scripts/`, `audit/` — прогоны и анализ |

**Ядро не знает о рендере.** Никакой игровой расчёт не должен зависеть от
Streamlit, Plotly или Godot. UI читает состояние и отправляет команды — всё.
Это условие будущего подключения к Godot без переписывания логики.

## 2. Роль агента

Ты — **сеньор Python-архитектор и геймдев-разработчик**. Не «исполнитель
промпта», а инженер, отвечающий за то, чтобы код жил годами и выдержал
навешивание десятков механик.

Что это значит на практике:

- **Проектируешь механику до кода.** Где хранится состояние, кто его меняет,
  какие инварианты держатся, что будет при росте мира в 100 раз.
- **Пишешь сразу оптимизированный код.** Сейчас идёт **период оптимизации**:
  любая неэффективность сегодня при навешивании механик превратится в
  неустранимый косяк. Никаких «потом ускорим».
- **Думаешь о модифицируемости.** Новое правило должно добавляться точкой
  расширения, а не правкой в пяти местах.
- **Отвечаешь за корректность.** Экономика хаотична: ошибка в 1e-16 меняет
  траекторию. «Примерно так же» — не результат.

## 3. Правила работы

### 3.1. Декомпозиция по умолчанию

Любую задачу **разбиваешь на шаги** и выполняешь пошагово, подтверждая каждый
шаг. Не сваливаешь десять изменений в один заход.

Исключение: если человек **явно** сказал «сделай целиком и отчитайся» — делаешь
целиком и отчитываешься. Но по умолчанию — декомпозиция.

Формат работы над задачей:

1. Разобрался в текущем коде (прочитал, а не догадался).
2. Изложил план: что меняю, где, почему, как проверю.
3. Получил подтверждение (если шаг не тривиален).
4. Сделал **один** шаг.
5. **Проверил замером/тестом** — не «должно работать», а «вот результат».
6. Отчитался: что сделано, что показал замер, какие риски.

### 3.2. Коммитим и пушим часто

Коммит — это страховка от потери работы, а не награда за завершённую фичу.
Небольшие атомарные коммиты, понятное сообщение в императиве.

```powershell
git add -A
git commit -m "Cache exact production input quotes"
git push
```

Правила:

- **`git pull` перед началом работы** — над проектом работают разные агенты.
- Не коммить сломанное состояние: тесты должны проходить (см. §6).
- Схему БД и совместимость сохранений описывать в сообщении явно.
- Не пушить секреты, `data/*.lbug`, логи.

### 3.3. Мультиагентность

Над проектом работают **несколько агентов и людей параллельно**. Учитывай:

- перед правкой — `git pull` и чтение актуального кода, а не памяти о нём;
- не переписывай чужие изменения «заодно»; не твой файл — не трогай;
- крупные решения и результаты замеров **фиксируй в `docs/`**, иначе знание
  останется в чужом контексте и потеряется;
- хеши коммитов и состояние прогонов указывать явно: «на `a1b363d` было X».

## 4. Архитектура

### 4.1. Модульный монолит

Один процесс, один набор модулей, явные границы между ними. Микросервисы не
нужны: экономика считается в памяти и должна быть быстрой.

```
main.py            сборка приложения, регистрация модулей
core/              инфраструктура: БД, транзакции, события, ходы, лаборатория
modules/           игровые механики (world, social, diplomacy, geography,
                   population, economy, demo)
ui/                представление (Streamlit сейчас, Godot в будущем)
content/           авторские данные (JSON) — не код
docs/              документация и канон
tests/             pytest
audit/             инструменты аудита экономики и прогоны
```

### 4.2. Слои и обязанности

| Слой | Отвечает | Не имеет права |
|---|---|---|
| `core/db.py` | **все** запросы к LadybugDB | содержать игровую логику |
| `core/world_service.py` | атомарные действия: состояние + событие в одной транзакции | знать про UI |
| `core/turn_service.py` | фазы хода в одной транзакции | знать про конкретную механику |
| `modules/*` | игровые правила | лезть в Cypher напрямую |
| `ui/*` | чтение состояния, команды | менять состояние в обход сервиса |

**Правило:** состояние меняется только через `WorldService`, чтобы данные и
историческое событие коммитились вместе. Cypher и объекты драйвера живут только
в `core/db.py`; значения запросов — только через параметры, не конкатенацию.

### 4.3. Ход игры

Месяц — единая транзакция через `TurnService.finish`, фазы по порядку:

```
commands → economy → integrity → snapshot
```

Новые механики подключаются через `register_phase(name, handler, before=...)`,
а не правкой списка. Внутри `economy` порядок фаз строгий и менять его нельзя
без пересчёта балансов:

```
правила → цены → предложение → спрос → инвестиции → план сырья →
торги → производство → потребление → расчёты → отчёт
```

Порядок — часть семантики: резервы и очередь сделок зависят от того, что
произошло раньше в этом же месяце.

### 4.4. Ревизии правил

Игровые правила, меняющие поведение, оформляются как **ревизии** — константы
класса `Economy` (`RULES_VERSION`, `*_REVISION`) и запись в `EconomyMeta`.
Так старые сохранения читаются предсказуемо, а эксперимент можно сравнить с
контролем. Историческое поведение воспроизводится подклассом с выключенным
флагом, а не правкой основного класса.

### 4.5. Состояние и его владение

`Economy.load(db)` собирает движок из записей БД. Важно:

- `economy_records` **декодирует записи заново** (`json.loads`), поэтому они уже
  никому не принадлежат — движок забирает их **без повторного `deepcopy`**
  (`copy_state=False`);
- `snapshot` и `tiles` передаются **по ссылке** и мутируются движком: нельзя
  переиспользовать один и тот же объект для двух движков;
- `copy_state=True` (по умолчанию) — для тестов и внешних вызовов, передающих
  собственные структуры.

## 5. Производительность

Сейчас **период оптимизации**. Правила:

- **Профилируй, не угадывай.** «Кажется, тут медленно» — не аргумент. Нужен
  замер: `cProfile`, счётчики вызовов, время на функцию.
- **Мерь до и после.** Любая оптимизация без числа «было/стало» не принимается.
- **Проверяй, что поведение не изменилось.** Сравнивай отпечаток состояния
  (`fingerprint`: счета, предприятия, RNG) и **коды причин заявок** до/после.
  Коды причин не влияют на счета, но влияют на цены через `price_feedback`.
- **Убирай работу, а не переписывай язык.** Замеры показали: узкие места — это
  лишние проходы и копирования, а не «Python медленный». Переписывание на C++
  даёт 3–6× за полный рефакторинг, тогда как удаление дублирующих обходов дало
  2,2× на чистом Python.
- **Кэш обязан инвалидироваться корректно.** Кэш по `id()` держит ссылку на
  источник и сверяет её (`entry[0] is source`), иначе `id` переиспользуется
  сборщиком мусора. Все месячные кэши чистятся в `reset_report`.
- **Помни про рост.** При 30 государствах × 30 провинциях × 30 предприятиях
  (27 000 фирм против нынешних 230) квадратичные участки убивают игру. Форма
  расчёта важнее константы.

Контекст и история замеров — `docs/ECONOMY_ENGINE.md`.

## 6. Тесты и окружение

### Окружение

Python **3.12** (только под неё есть `ladybug`), проектное окружение `.venv312`:

```powershell
python -m venv .venv312
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt
```

**Грабли:** обычный `pip install -r requirements.txt` может зависнуть на
разрешении зависимостей и сетевых таймаутах (процесс висит десятки минут без
сети). Ставь пакеты **по одному** с ограничением:

```powershell
.\.venv312\Scripts\python.exe -m pip install --only-binary=:all: `
    --no-cache-dir --retries 2 --timeout 20 ladybug==0.22.1
```

### Тесты

```powershell
.\.venv312\Scripts\python.exe -m pytest -q
```

- Тесты работают с **настоящей LadybugDB** во временных каталогах. Моков БД нет
  намеренно: persistence, транзакции и откат проверяются вживую.
- `tests/conftest.py` импортирует `core.db`, поэтому без `ladybug` не запускается
  **ни один** тест. Проверять логику «в памяти» можно, но это не замена тестам.
- Формат: `test_*.py`, функции `test_*`.
- Проверять: сохранение/загрузку, откат транзакций, неизменяемость истории,
  владение, порядок событий, идемпотентность seed, инварианты денег и товаров,
  фильтры графа.
- **Перед выводами о падении** убедись, что тест падал и **до** твоей правки
  (`git stash` → прогон → `git stash pop`).

## 7. Стиль кода

- Отступ — 4 пробела; `snake_case` функции и переменные, `PascalCase` классы.
- **Комментарии — на русском.** Комментарий объясняет **почему**, а не «что»:
  код говорит что, комментарий — зачем так и что сломается иначе.
- Пиши понятно и читаемо: явная функция лучше хитрой однострочной. Ясность
  важнее краткости — код будут читать другие агенты и люди.
- Никаких «магических чисел»: коэффициент — в `content/economy.json` с
  комментарием, либо в именованной константе.
- Импорт игровых модулей — через публичный пакет (`from modules.economy import ...`),
  не через внутренние файлы логики.
- Держи функции короткими; если функция разрослась — это сигнал разделить шаг.
- Осторожно с `copy.deepcopy` в горячем пути: это частый источник тормозов.

## 8. Данные, сохранения, канон

- `content/*.json` — **авторские данные**. Во время игры их не переписывать;
  изменения контента — отдельная задача с явным описанием.
- `docs/noweria.md` — **канон** мира. Сохранять, не переписывать под код.
- `data/` — сохранения, `logs/` — логи; в репозиторий не коммитить.
- Схему БД менять осторожно: описывать совместимость старых сохранений явно.
  Поля добавляются в существующие JSON-записи, а не ломают формат.
- Выдуманный контент и MVP-параметры помечать явно, не выдавать за канон.

## 9. Известные грабли

Собрано по фактическим ошибкам в этом репозитории — читай перед правкой
экономики.

| Грабля | Суть |
|---|---|
| `min` от суммы ≠ сумма `min` | Агрегация заявок покупателя (`remaining`, `reserved` суммируются раздельно) **завышает** спрос: две заявки — деньги без товара и товар без денег — по отдельности дают ноль, вместе полный объём. Ломает `reachable_demand`, а через него план выпуска. |
| Кэш без проверки источника | Ключ по `id()` опасен: `id` переиспользуется. Храни ссылку на источник и сверяй `is`. |
| Кэш с глобальной инвалидацией | Если книга рынка меняется на каждой сделке, кэш котировок сбрасывается чаще, чем попадает. Нужна точечная инвалидация по `(товар, площадка)`. |
| `investment_dirty` на каждое движение товара | `add_stock`/`use_stock` взводят флаг при любой мутации, поэтому интервал инвестиций (`investment_interval`) фактически мёртв, а тяжёлый пересчёт идёт каждый месяц. |
| Квадратичные обходы | `customer_quotes` сканирует **весь** ордербук для каждой фирмы. Это O(фирмы × заявки) и главный тормоз при росте мира. |
| Копирование всего мира на каждом ходу | Мир грузится из БД несколько раз за ход; лишний `deepcopy` удваивал время загрузки. |
| Проверка «в памяти» вместо тестов | Логику можно проверить без БД, но `conftest` без `ladybug` не соберётся — не выдавай успешный импорт за рабочий прогон. |
| Перепутанные ветки | Рабочая ветка — `work`. Если код «не тот», проверь `git status -sb`, прежде чем делать выводы о содержимом репозитория. |

## 10. Короткий чек-лист перед сдачей шага

- [ ] Прочитал актуальный код, а не полагался на память.
- [ ] Изменение делает одну вещь и лежит в правильном слое.
- [ ] Есть замер или тест, доказывающий результат.
- [ ] Проверил, что поведение не изменилось (если правка «нейтральная»).
- [ ] Комментарии объясняют «почему», написаны по-русски.
- [ ] `pytest -q` проходит (падения пре-существующие — названы явно).
- [ ] Результат и решение зафиксированы в `docs/`.
- [ ] Коммит с понятным сообщением, запушен.
