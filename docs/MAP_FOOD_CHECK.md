# Может ли карта обеспечить население хлебом?

**Да — физически может на проверенном сохранении.** Проверена карта seed 73129,
месяц 240, с текущей закупочной политикой с самого старта. Новых заводов,
ресурсов или стартовых запасов в расчёт не добавляли. Это расчёт выполнимого
месячного потока, а не новая симуляция поведения агентов.

| Показатель | Единиц хлеба в месяц |
|---|---:|
| Базовая потребность населения | 1664,25 |
| Фактическое потребление населения, среднее за месяцы 211–240 | 727,56 — 43,72% потребности |
| Фактическое производство хлеба за тот же период | 881,63 |
| Выполнимая доставка населению при согласованном физическом распределении | 1664,25 — 100% потребности |

Полное обеспечение найдено **для каждого места проживания**, а не только по
сумме карты. Объём ограничен потребностью: 1664,25 здесь не объявляется абсолютным
максимумом хлебного производства карты.

## Что учтено

Решена линейная задача для цепочки зерно → мука → хлеб и древесины как топлива.
Каждый завод ограничен существующей мощностью; зерно и древесина — природным
ресурсом соответствующей провинции. У труда и природного ресурса общий предел,
а не отдельный лимит на каждый завод. Учитываются рецепты, точные расположения
предприятий и населения, реальные доступные маршруты и стоимость доставки.
Фрахт считается по расстояниям и весам текущего движка. Пропускная способность
транспорта не ограничивается, как и в игре.

Сырьё доставляется от добычи к переработке, хлеб — к населению. Не разрешено
использовать складские запасы: цепочка должна обеспечиваться новым ежемесячным
выпуском. Потоки не тратятся дважды. В физически существующих закрытых заводах
допускается перезапуск; финансирование перезапуска здесь не проверяется.

Выполнены два расчёта:

1. Только хлеб населения, без потребностей остальных отраслей.
2. Хлеб населения **с сохранением среднего выпуска остальных отраслей и
   закупленного хлеба собственников за месяцы 211–240**. У других отраслей
   сохраняются затраты труда и общего природного ресурса; им поставляется
   требуемое сырьё хлебной цепочки, прежде всего древесина. Остальные их цепочки,
   не связанные с этими четырьмя товарами, отдельно не оптимизируются.

В обоих случаях населению можно доставить 100% потребности. Второй расчёт также
доставляет собственникам прежние 152,14 хлеба в месяц. Это не достигается
перенаправлением всего их хлеба населению или остановкой остальных производств.
Новых потребностей, роста прочих отраслей и снабжения строек расчёт не требует.

Один найденный вариант второго расчёта:

| Выпуск цепочки | Объём в месяц |
|---|---:|
| Зерно | 1743,74 |
| Мука | 1453,12 |
| Хлеб, включая собственников | 1816,40 |
| Древесина, включая потребности других отраслей | 335,11 |

После нахождения максимального покрытия потребности второй проход минимизирует
зарплату и фрахт. В этом варианте фрахт всех рассматриваемых потоков — 42,88
золота в месяц, зарплата четырёх отраслей — 311,51. **Это не рыночная цена хлеба**
и не полные расходы экономики: сюда не входят прибыль продавцов, конечный налог,
зарплата других отраслей и распределение доходов.

## Что доказано, а что пока нет

Доказана физическая выполнимость одного регулярного распределения потоков на
этой карте при заданных мощностях. Поэтому нехватка местного зерна, леса,
мельниц, пекарен или отсутствие путей **не делают нынешний дефицит хлеба
неизбежным**. Дорогая доставка при реальных ценах всё ещё может влиять на решения.

**Не доказано**, что обычный рынок способен оплатить и поддерживать найденный
вариант. Не ограничены деньги конкретных покупателей и предприятий, текущие
заявки, наценки, прибыльность, сроки запуска и порядок торговли. Это также не
доказательство вины отдельного алгоритма агента: разрыв может возникать из-за
распределения денег, цен, планирования и их сочетания. Результат не переносится
автоматически на другие карты или начальные состояния.

Это полезное сужение задачи: на данном сохранении **одной физической бедностью
карты хлебный дефицит не объясняется**. Следующая финансовая проверка должна
сохранять те же мощности и карту и выяснять, кто не может оплатить нужные потоки.
Новая правка поведения агентов в этом исследовании не добавляется.

## Проверки и данные

Сохранён [выполнимый план со всеми потоками](research/map_food_73129.json),
хешами checkpoint, трассы и скрипта. Проверены все ограничения решателя и полное
покрытие потребности по каждому месту проживания; максимальное превышение
ограничения — менее 1e-12. Исходное сохранение не переписывается: расчёт ведётся
на отдельном загруженном экземпляре, где выпуск прочих отраслей заменён средним
для выбранного окна. После подготовки задачи состояние и RNG не меняются.

Шесть тестов проверяют рецепты всей цепочки, общий природный ресурс зерна и льна,
общий труд, разрыв маршрута, невозможность незаметно отбросить недостижимый спрос
другой отрасли и сохранение потребления собственника. Все шесть прошли.

Для решателя нужен необязательный SciPy 1.17.0; зависимости самой игры не меняются.
В рабочей среде использован уже установленный SciPy отдельного системного Python.

```bash
# При необходимости установить только в исследовательское окружение:
python -m pip install -r requirements-research.txt

python scripts/check_map_food.py --checkpoint /path/engine-240.pickle \
  --trace /path/monthly.jsonl --solver-python /path/to/python-with-scipy \
  --out /tmp/map-food.json
python -m pytest -q tests/test_map_food.py
```

Без `--trace` сохраняется выпуск других отраслей и хлеб собственников только
последнего месяца checkpoint. В этом исследовании использована трасса
`/workspace/opportunity-use/fresh-73129/monthly.jsonl` и checkpoint
`/workspace/input-bid-promotion/fresh/seed-73129/engine-240.pickle`.
Pickle разрешён только из собственных доверенных состояний. Для тестов SciPy
должен быть доступен в `python` из PATH; иначе эти дополнительные тесты пропускаются.
