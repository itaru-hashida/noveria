# V4: перераспределение на остаточном графе

Запуск из корня: `python -B -m scripts.experiment_v4_residual`.
Эксперимент использует готовые допустимые рёбра одного snapshot для всех
решателей. Подготовка мира, маршрутов и snapshot находится вне таймеров.
На живом рынке эталон решает лексикографическую задачу по независимым
компонентам. Времена одного прогона в миллисекундах.

| Сценарий | Объём Greedy | Объём Repair | Объём exact |
|---|---:|---:|---:|
| Дешёвый лот занят старшей заявкой | 10 | 11 | 11 |
| Равный приоритет | 5 | 5 | 5 |
| Разные объёмы заявок | 7 | 7 | 7 |
| Ограниченный бюджет | 8 | 8 | 8 |
| Требуется пять рёбер | 2 | 2 | 3 |
| Seed 73129 | 3433.570491 | 3434.405641 | 3434.405641 |

Seed 73129, 1669 рёбер. Время массива распределения Repair составило
6.26 мс, Greedy с упаковкой результата — 24.14 мс, exact с упаковкой —
3504.87 мс. Отдельное применение 570 сделок заняло 20.01 мс.
Проверки ограничений по заявкам, цене, бюджету и запасам прошли.
Применённый объём совпал с рассчитанным, итоговые деньги и товары
сохранились. В существующий адаптер применения передаётся полная цена
из котировки, включая перевозку.

NumPy обрабатывает массивы активных рёбер и остатки по заявкам.
Python управляет раундами. Поиск ограничен 64 перестановками через три
ребра. Перестановка сохраняет исполнение вытесняемого покупателя и
учитывает изменение его расходов. Для нового исполнения выбирается
старшая из найденных заявок. Это локальное правило приоритета.
На seed 73129 с эталоном расходятся 22 исполнения против 28 у Greedy.
Первое расхождение Repair по рангу — заявка `1-1100`, недобор 0.0462.
При цепочке `c → s0 → a → s1 → b → s2` Repair сохраняет объём 2.
Эталон переносит обе существующие сделки и получает объём 3.

Упаковка результата и применение остаются на существующих границах.
Экспериментальный решатель доступен через явный параметр `solver`
shadow-адаптера. Время всего торгового прохода здесь отдельно не измерялось.
