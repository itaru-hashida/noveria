# Аудит CSR vs exact LP: seed 73129

Эксперимент выполнен на одном и том же snapshot: 910 покупателей, 616
продавцов, 1669 допустимых рёбер. V3, runtime и алгоритмы не изменялись.
Полный pytest не запускался.

## Что действительно оптимизирует эталон

`allocate_market_exact` решает следующую последовательность:

1. максимальный общий физический объём;
2. при фиксированном объёме — максимальное заполнение покупателей по порядку
   `buyer_limit desc → unmet_age desc → buyer_id asc`.

Для каждого ребра допустимость цены проверяется как:

```text
seller_price + freight <= buyer_limit + 1e-12
```

Денежное ограничение — сумма `quantity * delivered_price <= buyer_budget`.
В live-adapter `buyer_budget` берётся из `order.reserved`, а не из свободной
кассы. Это соответствует текущей семантике V3 reservation.

В objective LP не входят минимизация цены продавца, минимизация доставки,
предпочтение конкретного продавца или порядок рёбер. Поэтому два решения,
одинаково заполняющие всех покупателей, могут различаться по продавцам и быть
равноценными относительно заявленной политики.

## Почему число 44 было неверным

Историческая проверка использовала ранжированный массив только справа:

```python
delta[index] < 0 and any(delta[rank[index + 1:]] > 0)
```

В левой части должно быть `delta[rank[index]]`. После исправления получается
39 прямых случаев: более приоритетный покупатель недополучил, а менее
приоритетный получил дополнительный объём. Поэтому «44 нарушения» — ошибка
аудитора, а не подтверждённое свойство CSR.

Если убрать произвольный ID tie-break, число существенных случаев не меняется:
все 39 классифицированы по различию `price_limit`; случаев, где причиной был
только `unmet_age` или ID, нет.

## Заключение

- LP корректнее CSR относительно утверждённой политики V4: он действительно
  фиксирует общий максимум и затем buyer-priority vector.
- Число 44 было ошибкой измерительного кода; корректное число прямых
  priority-нарушений — 39.
- 16 отличий объясняются масштабированием `1e6`; существенных денежных
  нарушений нет.
- 189 строк относятся к конкуренции/компенсации потоков и сами по себе не
  являются отдельным доказательством ошибки LP. Они отражают то, что CSR не
  оптимизирует buyer-priority vector и выбирает другой допустимый поток.
- Если экономическая политика должна дополнительно предпочитать дешёвых
  продавцов или дешёвую доставку, этого требования сейчас нет ни в CSR, ни в
  LP objective; это неполнота спецификации, а не найденная ошибка решателя.
