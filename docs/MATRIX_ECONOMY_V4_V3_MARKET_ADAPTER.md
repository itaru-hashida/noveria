# V4: shadow-мост живого рынка V3

Добавлен `shadow/v4_market_adapter.py`. Это первый изолированный шаг
интеграции, без изменения V3 и без подключения к `monthly_boundary`.

Путь данных:

1. Берутся активные живые `buy`/`sell` orders V3.
2. Для каждой пары одного товара вызывается существующий `engine.landed`;
   недоступный маршрут исключается, а freight/distance/path сохраняются.
3. V4 получает `MarketSnapshot`. Денежный budget равен текущему `reserved`
   заявки, то есть сохраняет семантику V3 `match`; свободная касса не
   добавляется. В V3 нет поля `unmet_age`, поэтому без отдельной карты оно
   равно нулю.
4. Каждая allocation применяется через существующий
   `commit_trade_atomic`, поэтому сохраняются списание резерва, stock,
   налоги, freight, отчёт сделки и инвалидация котировок.

Проверен focused smoke на seed `73129`: одна реальная sell-заявка и одна
buy-заявка, маршрут между ними доступен, V4 распределил `3.0`, применение
создало одну сделку, остатки стали `buy=0`, `sell=2`.

Ограничения текущего шага:

- месячный ход всё ещё вызывает V3 matching; shadow-мост не подменяет его;
- не реализованы сбор всех фаз заявок, `local_only`, household adaptive
  top-up, match observations и финализация причин/статусов всех невыполненных
  заявок;
- solver по умолчанию — текущий V4 `allocate_market`; быстрый 2-LP кандидат
  пока остаётся экспериментом и не объявляется production-корректным.

Следующий дешёвый шаг — подключить этот мост в отдельный режим одного
месячного хода с rollback/снимком состояния и сравнить applied trades с V3,
не меняя основной путь до проверки паритета.
