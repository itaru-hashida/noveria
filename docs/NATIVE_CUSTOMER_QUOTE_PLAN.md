# Native-прототип V3: выбор первого вычислительного участка

Дата: 12.11.2026. Ветка: `experiment/parallel-agent-planning`, база `f0149dc`.
Это отчёт шага 1. Код движка не менялся; реализация C++, флаги и интеграция
в `step()` на этом шаге не выполнялись.

## 1. Выбранный участок

Первый кандидат — `_customer_quote_index(tile_id, good, orders)` в
`modules/economy/v3.py`: построение упорядоченных пар `(order, freight)` от
площадки производителя к заявкам покупателей.

Причины выбора:

- строки для разных площадок назначения независимы;
- порядок заявок внутри строки задан исходным `orders`;
- расчёт не использует RNG, счета, склады, резервы и сделки;
- фильтры `participant`, `remaining` и `status` остаются в последовательном
  `customer_quotes`;
- естественная единица пакета — `(orders, len(orders), good)` для нескольких
  площадок.

## 2. Разбор кандидатов

| Участок | Входы и выходы | Общее состояние, мутации и commit | Независимость и порядок |
|---|---|---|---|
| `recover_enterprises` | Читает прогноз, котировки, деньги, склады и резервы; рассчитывает финансирование | Переводит деньги, меняет статус, отменяет офферы, меняет резервы и отчёт | Нельзя параллелить по фирмам: перевод владельца и повторное открытие влияют на следующие фирмы |
| `project_requests`, `project_candidate` | Читают рынок, спрос, проекты, труд, ресурсы и деньги; выбирают проект | Последовательно резервируют ресурсы, создают проекты и меняют отчёт; `profile()` может вызывать RNG | Не подходят для точного параллельного прототипа: ранний commit меняет ограничения следующих кандидатов |
| `_market_book` | Читает цены, площадки и ID офферов и маршруты; выдаёт отсортированную книгу и котировки | Меняет только кэши и необязательную диагностику; игровой commit отсутствует | Книги независимы по `(sell_list, buyer_tile, good)`, но 95,6% обращений уже попадают в кэш |
| `landed` | Читает маршрут, вес, тариф и цену; выдаёт полную цену, доставку, расстояние и путь | Меняет только кэш | Независим, но это слишком мелкий примитив с вызовами из разных изменяющихся фаз |
| `quoted_cost` | Читает книгу, живые `remaining`, справочные и recovery-цены; выдаёт стоимость, ceiling и покрытие | Меняет только кэш | Отдельный вызов чист, но вызовы чередуются с изменениями заявок и рынка; общий пакет менял бы границы фаз |
| `customer_quotes`, `_customer_quote_index` | Читают заявки товара, площадки, компоненты маршрутов, вес и тариф; выдают заявки и доставку | Меняют только кэши; живые фильтры выполняются снаружи | Строки `_customer_quote_index` независимы по площадкам; исходный порядок заявок сохраняется |
| `reachable_demand` | Читает группы спроса, книгу и остатки; выдаёт достижимый спрос | Мутирует только локальную рабочую карту `remaining` | Потенциально независим между фирмами на фиксированном снимке, но слишком широк для первого ядра |

## 3. Контракт native-вызова

Ключ пакета:

```text
(id(orders), len(orders), good)
```

Площадки назначения получают числовые индексы в порядке канонического `tile_id`.
Маршруты по-прежнему вычисляет существующий Python `path()`; C++ получает только
числовые расстояния и доступность.

Входные массивы:

```text
order_tile:       int32[n]    # buy-заявки товара в исходном порядке
order_component:  int32[n]
seller_component: int32[m]
distance:         float64[m x n]
reachable:        uint8[m x n]
weight:           float64
transport_rate:   float64
```

Результат с фиксированной ёмкостью по площадкам:

```text
counts:        int32[m]
order_indices: int32[m x n]
freight:       float64[m x n]
```

Для каждой площадки C++:

1. отбрасывает недостижимые заявки и заявки из другой route component;
2. сохраняет исходный порядок заявок;
3. вычисляет строго `distance * weight * transport_rate` слева направо, без
   `fast-math` и изменения порядка операций;
4. пишет только в заранее назначенную строку результата.

Python последовательно превращает индексы в существующие объекты заявок и
заполняет `_customer_quotes_cache` в порядке площадок. Игрового commit нет:
меняются только внутренние кэши.

При потоках площадки делятся на статические диапазоны. Каждый worker пишет
только свои строки; reduction отсутствует. Порядок завершения потоков не влияет
на результат.

## 4. Последовательная часть

Остаются в Python и в прежнем порядке:

- `shuffled()` и любой RNG;
- выбор момента снимка `orders`;
- `customer_quotes`: исключение собственной заявки, проверка
  `remaining/status`, вычисление `price - freight`;
- заявки, сделки, деньги, склады, резервы, проекты и отчёты;
- применение native-результата к кэшам;
- весь остальной `step()`.

V3 по умолчанию должен остаться на старом пути. Новый путь допускается только
под явным `native_kernel=serial|threads`; при недоступном расширении нужен
Python fallback.

## 5. Проверки следующих шагов

- побитовое сравнение `freight`, индексов и порядка строк с Python;
- пустые заявки, недостижимые маршруты и несколько route component;
- совпадение повторных обращений и поведения кэша;
- Python fallback при отсутствии расширения;
- режимы `off`, `serial`, `threads`, включая `workers=1/2/4`;
- 1, 12 и 36 месяцев, seed `73129` и минимум seed `17`;
- помесячно: котировки, заявки, сделки, счета, склады, резервы, RNG state и
  `validate()`;
- отдельно `pack`, `native call`, `apply`, затем полный `step`;
- потоки только после отсутствия расхождений у serial-варианта.

## 6. Верхняя граница выигрыша

Замер текущего HEAD: `seed=73129`, 12 месяцев, `warmup=2`, `detail=none`.

Команда:

```powershell
python audit/profile_run.py --seed 73129 --months 12 --warmup 2 --detail none --top 45
```

Результаты cProfile:

- `_customer_quote_index`: 0,717 с за 12 ходов, около 59,8 мс/ход
  накопительно;
- полный ход: 0,758 с/ход.

Отдельная проба рыночной картины без cProfile дала `customer_quotes` около
65 мс/ход вместе с вложенными вызовами; её абсолютные значения также включают
накладные расходы обёрток.

Это оптимистичный потолок, а не прогноз. Упаковка, распаковка и расчёт
дополнительных площадок уменьшат выигрыш. Порог 20 мс/ход достаточен для
проверки гипотезы, но пока не доказан. Если serial-вариант не даст устойчивого
выигрыша полного `step`, к потокам переходить не следует.
