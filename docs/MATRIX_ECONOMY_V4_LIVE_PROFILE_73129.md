# Профиль V4 live market — seed 73129

Профиль запускается через `scripts/profile_v4_live_market.py`. Мир и заявки
подготавливаются один раз; затем route/snapshot повторяются на том же живом
состоянии, а 2-LP повторяется на одном и том же неизменяемом snapshot.
Есть один cold-прогон и пять прогретых повторов; в отчёте используются
медианы прогретых повторов.

## Результаты

| Участок | Cold | Warm median |
|---|---:|---:|
| Полный route+snapshot | 220.8 ms | 317.3 ms |
| Python route-часть после `landed` | 103.0 ms | 193.1 ms |
| Реальные вызовы `engine.landed` | 28.1 ms | 27.2 ms |
| `MarketSnapshot.from_rows` | 85.3 ms | 88.1 ms |
| Измерительный перебор same-good пар | 30.0 ms | 24.3 ms |
| `_constraints` | — | 50.8 ms |
| Первый `linprog` (volume) | — | 69.7 ms |
| Второй `linprog` (priority) | — | 88.6 ms |
| Всего 2-LP | — | 212.7 ms |

Warm route timing включает Python-обход всех заявок и служебные проверки
адаптера. Он заметно шумнее cold-прогона, поэтому для решений использована
медиана, а не единичный лучший запуск.

## Размеры и счётчики

- buyers/sellers на входе: `910/630`;
- проверено same-good пар: `51,042`;
- вызовов `engine.landed`: `48,450`;
- cache hits: `48,450` на прогретом повторе;
- matrix: `2436 x 1669`;
- non-zero: `5007`;
- dense storage: `32,525,472` bytes.

## Оценка без переписывания

Разбиение по пяти товарам уменьшает оценочный dense storage до `5,571,696`
bytes, то есть примерно на **82.9%**. CSR для текущей матрицы оценивается в
`69,832` bytes, примерно на **99.8%** меньше dense; с отдельными CSR-группами
оценка около `108,824` bytes. Это оценка памяти и размера операций, а не
замер ускорения: группировка потребует отдельного решения LP на группу и
может увеличить число solver calls. Ничего из этого эксперимента не
внедрялось.

## TOP-3 узких места

1. Python-перебор и сборка route-пар — около `193 ms` warm median.
2. Второй priority `linprog` — около `88.6 ms`.
3. Построение `MarketSnapshot` — около `88.1 ms` (сборка `_constraints`
   отдельно занимает около `50.8 ms`).

Вызовы `engine.landed` сами по себе занимают около `27.2 ms` и полностью
попадают в кэш на прогретом повторе; это не главный bottleneck.
