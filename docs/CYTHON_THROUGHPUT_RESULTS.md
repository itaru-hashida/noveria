# Throughput Cython по независимым мирам

Замер выполнен на Linux в отдельном окружении Python 3.12 с Cython 3.3.1 и
Ladybug 0.22.1. Это throughput нескольких независимых миров, а не ускорение
одного хода внутри одного мира.

Команда использует `audit/native_throughput.py`. Каждый worker создаёт свой
мир, БД и RNG; после warmup выполняет `validate()` после каждого месяца.

Стандартная карта: 40x30, 1200 клеток, 466--478 счетов, 244--256 фирм.
Четыре seed: 17, 42, 101, 73129. Три измеряемых месяца и один warmup.

| режим | executor | workers | wall с созданием миров | throughput | средний ход после warmup |
|---|---:|---:|---:|---:|---:|
| V3 | serial | 1 | 11.873 с | 1.011 мес/с | 498.3 мс |
| Cython | serial | 1 | 11.883 с | 1.010 мес/с | 478.4 мс |
| Cython | threads | 4 | 12.723 с | 0.943 мес/с | 2392.2 мс на мир |
| Cython | processes | 4 | 6.102 с | 1.967 мес/с | 619.2 мс на мир |

Вывод:

- `with nogil` в уже перенесённых фазах недостаточен для параллельного полного
  хода: потоки конкурируют за оставшиеся Python-фазы и становятся медленнее.
- Отдельные процессы почти удваивают throughput четырёх независимых миров, но
  это не уменьшает latency одного хода игрока.
- Сначала переносим тяжёлые последовательные фазы в общий Cython state; потом
  повторяем этот стенд, чтобы увидеть, когда threads начинают масштабироваться.

Дополнительная проверка большой карты: 80x60, 4800 клеток, 493--510 счетов,
271--288 фирм, два seed, два измеряемых месяца, process pool из двух workers:
1.032 с среднего хода внутри worker и 0.468 месяца/с с созданием миров.
