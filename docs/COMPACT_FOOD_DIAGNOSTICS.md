# Компактная диагностика питания

Каждый игровой месяц содержит `food_diagnostics` со схемой 1. Она не меняет
решения, очередь, RNG или денежные потоки. Если дефицита и ошибки учёта нет,
сохраняются только итоговые количества; подробные таблицы пусты.

При дефиците сохраняются:

- бюджет до покупок, начальная еда, котировки, покупки, бюджет после торгов
  **до зарплат и распределения прибыли**, доходы и расходы месяца по причинам;
- по недостающему товару: невыставленная часть и обеспеченный остаток,
  ссылки на заявки, результат исполнения и самый дешёвый оставшийся маршрут;
- единая таблица остаточных продаж базовой еды, без копий для каждого покупателя;
- единая таблица производителей пищевой цепочки: план, выпуск, ожидаемая маржа,
  прогноз спроса, фактически связывающие ограничения и закупки входов;
- связи производителей через рецепты товаров и межгосударственные платежи
  по товарам, включая налог и доставку.

Таблица поставщиков по товару — индекс для дальнейшего расследования,
не утверждение, что каждый поставщик был достижим, выгоден и мог обслужить
всех покупателей одновременно. `cheapest_remaining` — доступная котировка
с доставкой, не совместная гарантия дополнительных покупок всех групп.
Полные списки кандидатов каждой заявки в этот блок не копируются.

## Честное покрытие

`accounting_unknown` — сумма абсолютных ошибок тождества:
дефицит = невыставленная часть + обеспеченная непоставка.
Ненулевой остаток остаётся видимым, а не списывается автоматически на бюджет.

`root_unknown` — дефицит, первопричина которого ещё не доказана. Сейчас весь
дефицит остаётся здесь: блок собирает проверяемые факты и цепочки, но не
выдаёт ближайший ограничитель за доказанное экономическое объяснение.
«Нет обеспеченного спроса» и «не хватило бюджета» не означают, что причина
полностью установлена. Наблюдения производства помечены отдельно; отсутствие
текущего плана не заменяется старым планом из предыдущего месяца.

В лаборатории блок включён в набор `diagnostics`: режим `summary` хранит
только итоги, режим `full` — также подробности. Идентификатор версии движка
включает диагностический модуль.

## Сжатый журнал

Только собственные доверенные pickle-файлы:

```bash
python scripts/record_food_diagnostics.py --checkpoint checkpoint.pickle --months 12 --out food.jsonl.gz
python scripts/record_food_diagnostics.py --inspect food.jsonl.gz
```

Первая команда **выполняет указанное число шагов симуляции**. Вторая читает
уже готовый журнал без новых шагов. Существующий файл не перезаписывается.
Экспорт потоковый, gzip; контекст карты, рецептов, коэффициентов и населения
пишется один раз и повторяется только при изменении. Записаны хеш исходного
сохранения, версия движка, хеши диагностического модуля и экспортёра.

На картах 17, 2026 и 73129 проверено по два месяца: вместе с контекстом карты
новый gzip-журнал занимает примерно 100–120 КБ на два месяца, ошибки
количественного разложения меньше 1e-12. Это измерение небольших проверочных
фрагментов, не верхний предел размера на любой карте. На карте 17 после
удаления несвязывающих ограничений — около 99 КБ на два месяца.

Эти размеры относятся к новому экспорту. Основной журнал игры по-прежнему
сохраняет свои заявки и сделки. Архивы старых прогонов не переписываются.
Отключение диагностических снимков для проверки нейтральности:
`engine.FOOD_DIAGNOSTICS = False`; обычная игра сохраняет их автоматически.
