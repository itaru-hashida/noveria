## Формулы

Именованные параметры находятся в shadow/agent_planner.py, контент не меняется:
alpha=0.35, output_buffer=0.25, input_buffer=0.10,
initial_sales_fraction=0.50. Это экспериментальные параметры, не канон.

- prior: agent_sales_forecast, иначе sales_forecast исходного сохранения V3.
- own: средние реальные продажи за последние три месяца.
- public: средний за последние три месяца объём покупок + обеспеченный
  неудовлетворённый спрос, делённый на число действующих продавцов товара.
  Это грубая равная доля публичного рынка, не гарантированный заказ; она
  не моделирует долю фирмы или доступность удалённого покупателя.
- При последнем input_limited: own=max(own, prior), чтобы не принимать
  ограничение предложения за исчезновение спроса.
- signal=max(own, public, current); F=max(current, (1-alpha)*prior+alpha*signal).
- Без своей истории: F=max(public,current); если оба нулевые, начальная
  проба capacity*0.5. Правило применяется только при отсутствии истории,
  не повторяется каждый месяц. Денег и товаров оно не создаёт.
- projected_stock=max(0, stock-min(stock,F));
  desired=clamp(F*(1+0.25)-projected_stock, 0, capacity).
  Непроданный запас останавливает выпуск; продажи без ограничений снижают
  прогноз через сглаживание, если публичный сигнал также исчезает.
- input_missing=max(0, output*ratio*1.10-available_stock).
  Опубликованный на продажу вход не считается доступным производству.
- Оборудование требуется целиком; в себестоимость входит только износ.
- План бинарным поиском ограничивается: оброк + зарплата + закупки <=
  доступная касса после обязательств. Предельная цена не превышает котировку
  и остаток маржи. Нулевой предел не заменяется произвольной ценой.

Используем существующую market_history V3: исполненная покупка остаётся в
volume/trade_gold/freight после исчезновения заявки из книги. unmet_solvent
считается только из обеспеченного остатка. Среднее месячных наблюдений
не суммирует один переносимый дефицит как новые покупки.

Дополнительные найденные ошибки: план продавца публиковался до бюджетного
сокращения; зарплата не входила в бюджет; оборудование списывалось как сырьё;
местный покупатель пропускался по совпадению площадки; исключение офферов фирм
из исполнительной книги лишало планировщик их публичных котировок.

Проверка чистого планировщика: tests/test_parallel_planning.py — история при
пустой книге, начальный публичный прогноз, ограничение кассой и зарплатой,
различение ограничения входами и падения продаж.

## Полный месяц (второй отдельный коммит)

`Economy.step(enterprise_planner=...)` оставляет штатный путь V3 по умолчанию.
Экспериментальный AgentTurn заменяет только планирование предприятий и подаёт
намерения в родительском процессе по готовности пакетов. Существующие склады
публикуются один раз до снимка; повторный sell не резервирует их заново.
Потребители получают первый доступ к своим местным складам, затем идут обычные
общие торги; остатки B2B-заявок проходят финальный штатный клиринг.

Исполнение использует Economy.order/match/produce/settle/record_market/save,
поэтому реальные лимиты цен, деньги, зарплата, налоги, перевозка, учёт стоимости,
износ, потребление, инвестиции и инварианты не дублируются в новом ledger.
Это осознанная замена ненадёжного исполнительного прототипа, а не расширение
состава агентов. Старые shadow.runner/producer/market_executor остаются
статическим аудитом отдельного снимка; для полной экономики использовать
shadow.compare_v3, а не результат выбрасываемого ledger.

Новый месяц действительно сохраняется и следующий читает его, а не V3-мир.
Полный вызов проходит через TurnService: одна транзакция, integrity, snapshot,
commit, уведомления. Внешний обработчик устанавливается только бенчмарком;
игровой путь по умолчанию остаётся V3. Дополнительный агентный прогноз хранится
в JSON предприятия; схема БД не меняется, старые сохранения читаются.

Пул прогревается отдельно через spawn до измерения месяцев. Количество
ожидаемых пакетов известно: после последнего результата нет polling timeout.
Снимок освобождается только после завершения всех futures, в том числе при ошибке.
Для проверки исполнения AgentTurn(replay=recorded_log) использует записанные
намерения и прогнозы в записанном порядке без пересчёта их при новой очереди.

Снимок получает реальные доступные деньги, а не деньги владельца, которые ещё
не переведены. Котировки входов берутся по собственному счёту фирмы из уже
построенных публичных книг; свои же предложения не считаются доступной покупкой.
Неинформативные строки истории нового предприятия (ничего не выставлено,
не продано и не выпущено) не считаются историей продаж. Начальная проба не
возобновляется каждый месяц: после первого плана прогноз хранится отдельно.
