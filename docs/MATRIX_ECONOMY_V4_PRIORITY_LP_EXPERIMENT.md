## Ограничение вывода

Это подтверждает совпадение только для данного snapshot. Простые строго
убывающие unit-веса не дают общего доказательства точной лексикографии при
других объёмах заявок и конфигурациях дефицита; поэтому быстрый solver нельзя
пока объявлять заменой exact.

Денежное ограничение имеет вид `sum(delivered_price * x) <= budget` для каждого
покупателя. Это side constraint на дуги, а не обычная сеть потоков. Поэтому
`SimpleMinCostFlow` не является точным drop-in решением без дискретизации денег
или дополнительной модельной трансформации.

Следующий самый дешёвый эксперимент — прогнать тот же harness на небольшом
наборе заранее сохранённых snapshot-ов с разными объёмами заявок. Установка и
оценка `highspy` с reuse basis оправданы только если такой набор найдёт
расхождение; после текущего совпадения это не самый дешёвый следующий шаг.
