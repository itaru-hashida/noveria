# Честный benchmark торговой фазы V3/V4

Запуск: `scripts/benchmark_v3_v4_trade_phase.py`. Raw CSV:
`docs/v3_v4_trade_phase_timings.csv`. Для каждого seed создавалась свежая
независимая копия подготовленного игрового state; создание мира и подготовка
заявок находятся вне таймеров. Было 5 прогретых повторов и один cold-прогон,
порядок V3/V4 чередовался.

## Warm median, ms

| Seed | V3 total | V4 total | V3/V4 |
|---:|---:|---:|---:|
| 17 | 74.962 | 503.977 | 0.149x |
| 73129 | 74.871 | 416.123 | 0.180x |
| 7 | 75.834 | 426.198 | 0.178x |
| 4231 | 78.681 | 634.618 | 0.124x |

Медиана по seed: V3 **75.398 ms**, V4 **465.088 ms**, отношение
**0.162x** (то есть V4 в этом измерении примерно в 6.2 раза дольше).
Это отношение стоимости фактически выполненных торговых фаз, а не чистых
решателей: V4 строит snapshot и глобально рассматривает пары, которых V3
отбрасывает индексами/локальными правилами.

## Разложение этапов

На seed `73129` (warm median):

| Этап | V3, ms | V4, ms |
|---|---:|---:|
| Подготовка котировок/маршрутов | 2.599 | 39.359 |
| Поиск допустимых сделок | 29.875 | 82.599 |
| Snapshot | 0 | 84.900 |
| Распределение | 2.804 | 177.296 |
| Применение сделок | 29.434 | 18.512 |
| Финализация | 10.081 | 2.455 |
| Итого | 74.871 | 416.123 |

Суммы стадий согласуются с total с небольшим timer gap. В V3 `distribution`
измеряет traversal matcher без commit; commit вынесен отдельно. В V4
`distribution` — 2-LP, `snapshot` вынесен отдельно, а apply — только
`commit_trade_atomic`.

## Где пути расходятся

- V3 выполняет отдельный `basic needs local_only` проход, затем общий
  matching; V4 одним вызовом распределяет глобально доступные пары.
- V3 строит индексированную книгу offers и route components; V4 shadow-мост
  перебирает buy×sell same-good пары и строит dense `MarketSnapshot`.
- V3 применяет сделки во время traversal и поддерживает собственные
  observations/reprice semantics; V4 применяет готовые allocation через
  `commit_trade_atomic`.
- household adaptive top-up и точные V3 match observations в V4 не входят.

Поэтому чистое сравнение “только распределение” пока невозможно без изменения
семантики V3: у V3 нет отдельного solver API, принимающего тот же заранее
рассчитанный список допустимых пар. Такой эксперимент не выполнялся.

## TOP-3 узких места V4

1. 2-LP allocation — около **177.3 ms** на seed 73129.
2. Построение `MarketSnapshot` — **84.9 ms**.
3. Поиск/перебор допустимых пар после вызовов маршрутов — **82.6 ms**.

У V3 основная стоимость сопоставимого прохода — применение сделок (**29.4
ms**) и поиск/котировки (**29.9 ms**). V3 не менялся, LP и экономика V4 не
переписывались, полный pytest не запускался.
